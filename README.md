# 피싱 길잡이
## 실행
모든 파일을 같은 폴더에 두고 index.html을 브라우저로 엽니다. 서버·설치·로그인은 필요하지 않습니다.
전화번호 112·1394는 일반 텍스트이며 전화 연결 기능은 없습니다.
공식 출처 링크를 여는 경우에는 인터넷 연결이 필요합니다.

## 데이터와 개인정보 — BRB-C06
app.js의 CASES는 공식 기관이 공개한 기록 10개를 요약한 학습용 자료입니다. 실제 사건 원문이나 피해자 응답 데이터가 아닙니다. 공개 예시·사례 요약·재구성을 구분하여 표시합니다.
공개사례_학습용데이터.json에 같은 사례와 기관 출처를 읽기 쉬운 형태로 함께 제공합니다. 실행에는 app.js에 내장된 데이터를 사용하므로 이 JSON을 따로 불러오지 않습니다. 사례 수정 시 두 자료를 함께 갱신해야 합니다.
피해자·담당자 이름, 개인 전화번호, 이메일, 주소, 계좌번호, 주민등록번호, 여권번호, 녹음·문자 원문을 포함하지 않습니다. 앱에서 사용하지 않는 학술문헌 저자명과 서지 데이터는 제외했습니다.
112·1394는 공식 도움 경로의 공공 연락번호로 개인 연락처가 아닙니다. 출처에는 기관명·공개일·공식 URL·확인일을 남겼습니다.
이용자는 정해진 선택지만 고릅니다. 선택값은 브라우저 메모리에서만 처리하며 저장소·분석 도구·서버 전송을 사용하지 않습니다. 새로고침하면 선택은 사라집니다. 외부 공식 링크를 열면 해당 기관의 사이트로 이동합니다.

## 비밀값과 환경 변수 — BRB-C07
필요한 환경 변수: 없음.
AI API와 외부 AI 서비스를 호출하지 않으므로 API 키·토큰·비밀번호가 필요하지 않습니다. .env 파일도 제공하거나 읽지 않습니다.
브라우저에 배포되는 HTML·CSS·JS에 키를 넣으면 숨길 수 없으므로 비밀값을 추가하지 마세요. 향후 AI 기능을 도입한다면 서버에서 환경 변수로 읽는 별도 설계가 필요합니다.

## 확인 방법
1. index.html에서 사례를 열어 개인정보 없이 기관 출처와 요약만 보이는지 확인합니다.
2. 내 상황을 선택하여 안내가 표시되는지 확인하고, 이름·전화번호·원문 입력칸이 없는지 봅니다.
3. 소스와 데이터에서 개인 식별정보·API 키·토큰이 없는지 확인하고 데이터_비밀값_점검.md와 대조합니다.

## 화면과 대응 순서
메뉴와 본문은 내 상황 확인 → 사례 보기 → 도움 경로 순서입니다. 영역 앞의 01·02·03 표기는 삭제했습니다.
사례 10개 각각에 공식 자료를 연결한 대응 절차를 추가했습니다. 사례의 기본 절차는 아직 실행하지 않은 경우를 기준으로 합니다. 이미 한 행동을 선택하면 피해 이후 대응이 먼저 나옵니다.
의심 앱 설치 시 통신 차단 → 안전한 별도 전화 신고·상담 → 삭제·초기화 도움 순으로 보여주며, 송금 피해가 함께 있으면 지급정지 요청을 삭제·방문보다 먼저 배치합니다.
일반 메신저 설치만으로 악성앱으로 단정하지 않습니다. 앱은 진단·신고·환급을 처리하지 않습니다.
대응 순서는 공식 자료를 앱에서 재구성한 것으로, 기관이 모든 사례에 동일한 단계 순서를 지정했다는 뜻은 아닙니다.
공식안내_사례별대조.md에서 사례별 근거와 공통 피해 후속 조치의 출처를 확인할 수 있습니다.

## 새 디자인과 카카오톡 추가 사례
남색·파랑·밝은 회색의 반응형 화면으로 전면 수정했습니다. C11은 공식 안내 기반 재구성 학습 예시로 기존 논문 표본 10개와 구분합니다. 친구 추가·서류 열람만 한 상태도 선택할 수 있으며, 이 상태만으로 감염을 판정하지 않습니다. 추가 앱 설치·정보 전달·송금은 실제 한 행동을 함께 선택하세요. 전화번호는 표시만 하며 전화를 걸지 않습니다.
